# Convention #28: components/ is grouped by domain with an optional dialogs/ subfolder

Each domain folder keeps its tabs/trees/panels at the root and files single-purpose modals under `dialogs/`; `common/` is reserved for genuinely cross-domain, store-free leaves. Several 1000+ line "god files" were split one-file-per-level, with non-JSX logic extracted into `lib/` hooks.



## Detail

**`src/components/` is grouped by domain, each with an optional `dialogs/` subfolder, and one file is one component's worth of work — this reverses the earlier "flat layout is fine" call.** That call was made at ~13 files; by the time it was revisited the directory held 46. The split is two axes: functional domain (`connection/`, `schema/`, `query/`, `grid/`, `menus/`, `shell/`, plus `settings/` and the pre-existing `ui/`), and within a domain, whether the component's main export is a single-purpose modal (`dialogs/`) or not (tabs, trees, panels, bars stay at the domain root). `common/` holds the components that are genuinely cross-domain leaves — `DriverBadge` (used by ad-hoc/connection-CRUD/tree/status-bar/workspace-picker) and `VanishedOriginNotice` (used by the tree, status bar, and the settings Origins section) were the first two, and there are eight now. The admission test is no longer a feel for how shared something is but the dependency rule in convention #60, which is objective: a shared component that carries its own copy goes here, one that imports a store or `@/lib/tauri` goes in its domain. Don't add to it casually; a component used by 2+ call sites *within the same domain* just lives in that domain, not in `common/`. **A god file is a layout problem too.** Five files had grown past ~1000 lines by carrying things that only *rendered* together: the explorer's eight dialogs and its four tree levels, the connection manager's rail and its form model, the CLI intent block inside `App.tsx`, `TabbedArea`'s tab header and empty state, and `DataGrid`'s row, chips, search box and draft row. They are now one file per level (`SingleDbExplorer` / `MultiDbExplorer` / `SchemaTableSection` / `SchemaTableRow`, `GridRow` / `ServerFilterChips` / `GridSearchInput` / `DraftRowView`, `ConnectionRail`, `WorkspaceTab` / `EmptyWatermark`), with the no-JSX logic in hooks under `lib/` (`useGridSelection`, `useColumnSizing`, `useCtrlWheelZoom`, `useConnectionForm`, `useCliIntents`). Two rules came out of doing it, and both cost a bug the first time they were ignored: **a hook is not a child component** when its effects must keep their position in the parent's effect order (`useCliIntents` — a child mounts *first*, which would put the CLI ahead of the launch-restore sequence of ADRs #8/#10); and **a wide hook signature is a cost to weigh, not an automatic veto**. That second rule started life as "stop extracting when the seam needs the whole component's state", on the grounds that `DataGrid`'s keyboard navigation, its `columns` memo and its toolbar each touch fifteen-plus pieces of grid state. They were extracted anyway in a later pass (3592 → 1301) and the reason the earlier call was wrong is the part worth keeping: what matters is whether a seam **owns** state or merely **borrows** it. `useCellEditing` and `useGridKeyboardNav` own theirs — four `useState`s and `activeCell` leave the component outright — so their inputs are identity props, not a live copy of the grid. The two that only borrow still earned the move, on different grounds: `useGridColumns` because its dependency array is a correctness invariant that should be read next to what it guards, `GridToolbar` because it is a self-contained widget. Where the input list stays long it is **grouped and named** (`grid`, `editing`, `display`, `meta`) rather than flattened, and each hook's doc says outright that the coupling is real. `DataGrid` still takes 41 props; none of this reduced that, and none of it was meant to. `CellEditor.tsx` is the one deliberately borderline case: it's dual-mode (a modal by default export, plus `CellEditorBody` re-exported for `SideEditorPanel`'s docked usage) and was filed under `grid/dialogs/` because the modal is its primary reason to exist. Every internal cross-import in `components/` — and `App.tsx`'s ~22 direct imports — already used the `@/components/...` alias (never relative) before this move, so relocating a file never required touching that file's own imports, only the imports *of* it; that invariant is why the move was a mechanical rename + specifier rewrite with zero logic changes, and it's worth preserving going forward (don't introduce relative cross-file imports at the `components/` top level, even between siblings in the same domain folder — keep using the alias, matching everything outside `settings/sections/`, which is the one pre-existing exception).
