# Convention #60: components/ui/ has a strict dependency rule, one density scale, three focus styles

`ui/` may only import `react`/`@radix-ui/*`/`lucide-react`/`cva`/`@/lib/utils` — nothing stateful — with density as `size` (`xs`/`sm`/`md`), `brand` (not `primary`) as the action color, and three named focus treatments in `ui/styles.ts`.



## Detail

**`components/ui/` is a library with a dependency rule, one density vocabulary, and three named focus languages — and `uiContracts.test.ts` holds the parts a test can hold.** The directory existed for a long time as "wherever the shadcn primitives went", which is how the app ended up with 65 hand-rolled icon buttons across 38 files, 35 native checkboxes across 24, eight `<select>` elements each carrying its own copy of a WebView2 workaround, and 219 native `title=` attributes against three files using the themed tooltip. The primitives were never the problem; the absence of a rule about them was. What is settled now:
    - **`ui/` may import `react`, `@radix-ui/*`, `lucide-react`, `cva` and `@/lib/utils`. Nothing else** — no store, no `@/lib/tauri`, no `react-i18next`, no `@/types`. This is the frontier, and it answers by construction the questions the directory used to settle by feel. **A shared component that carries its own words belongs in `common/`**, which is why `ConfirmDialog` and `PasswordInput` live there; **one that does IO belongs in its domain**, which is why `FkCombobox` moved to `grid/` after 375 lines of it — a quarter of the directory — sat in the shared layer importing a grid store. It also neuters gotcha #1 by construction: an unstable Zustand selector inside a primitive arrives in a hundred call sites at once. There is exactly one recurring temptation — making the tooltip delay a preference — and the answer is to pass `delayDuration` to the `TooltipProvider` at each of the three window roots, which already reach stores.
    - **Density is `xs`/`sm`/`md` = `h-7 text-xs` / `h-8 text-xs` / `h-9 text-sm`, and the prop is always `size`.** Where the native HTML attribute collides (`input`, `select`), `Omit` it from the props type rather than renaming the prop — `Input` carried an `inputSize` for exactly that reason long after the `Omit` had made it unnecessary. `lg` and the `icon*` sizes sit outside the scale on purpose: an icon size is a *shape*, not a density.
    - **`brand` is the action colour and `primary` is not.** `--primary` is near-black in light themes and near-white in dark ones (`index.css`); `--brand` is documented in `lib/themes.ts` as the one saturated colour the app may spend on affordances meaning "do this". Twelve checkboxes and five inline links used `primary` and rendered grey beside twenty that rendered blue. Note this is a two-token conflict, not three: every `accent-foreground` in the tree is `text-accent-foreground`, the foreground of the `--accent` *surface*, unrelated to the CSS `accent-color` property.
    - **Three focus languages, named in `ui/styles.ts`, and the legacy fourth is gone.** `fieldFocus()` is the field (the border turns brand, a soft 3px halo sits against it); `CONTROL_FOCUS` is a button or switch (a 2px ring detached by an offset — and `ring-offset-background` is not optional there, or the offset falls to Tailwind's default white and paints a white gap on a dark theme); `CONTROL_FOCUS_TIGHT` is the same ring with no offset, for chrome packed too tightly for one. The `ring-1 ring-ring` that sixteen call sites used was never chosen — it is what focus looked like before the visual overhaul, kept alive because there was nowhere to take the current treatment *from*.
    - **`fieldFocus` is a lookup over three literal strings, and must never become an interpolated template.** Tailwind's JIT scans source files as *text*, so a class assembled at runtime is never generated: no build error, no failing test, just a field that silently stops highlighting. The same rule governs `REVEAL_ON_HOVER`, keyed by group name (`row` and `field` genuinely nest — a document row holds fields with their own hover actions, and an unnamed `group` binds to whichever ancestor is nearest).
    - **`cva` does not merge classes; the `cn` inside the component does.** So "the consumer's `className` wins" can only be asserted on rendered output — `buttonVariants({ size: "sm", className: "h-6" })` still contains `h-8`, and a test against that string proves nothing. Both `button.test.tsx` and this note exist because the obvious test is the wrong one.
    - **`SimpleTooltip` supplies its own `TooltipProvider` when none is in scope** (a sentinel context in `tooltip.tsx`). Radix throws outright with no provider above it and offers no way to ask, so before this, putting an `IconButton` inside a component made that component unrenderable in any tree lacking one — every test touching it had to know to wrap it, and the first that did not failed with a stack trace pointing at Radix rather than at the cause. The three window roots should keep declaring theirs: one shared provider is what makes the hover delay shared.
    - **`IconButton` requires `label` and omits `title` from its props type.** That is the whole enforcement mechanism for the tooltip split: a compile error rather than a regex, so it cannot drift and needs no allowlist. `nativeTitle` is the escape hatch for the one place a native `title` is correct — inside open menu content, where Radix's tooltip fights the menu's portal handling (`tooltip.tsx` documents it).
    - **`NativeSelect` keeps `bg-background text-foreground` in its cva *base*, never in a variant, and never `bg-transparent`.** WebView2/Chromium paints a select's native popup from the trigger's own colours, so a transparent trigger opens an OS-light popup however dark the theme is — a Windows-only, dark-theme-only, popup-open-only bug that six files each remembered to work around, in four spellings of the surrounding chrome.
    - **A primitive is created on first adoption, never in advance** (the norm `segmented.tsx` records). A `SectionLabel` was written during this work and deleted the same day: it had no real consumer, because the two candidates turned out to carry an icon it did not model and a style it did not share. The actual duplication was the class string, and `MICRO_HEADING` fixes that without imposing an element — which matters, since several of those sites are an `<h4>` or an inline `<span>` in a flex row.
    - **`uiContracts.test.ts` guards what a test can guard, and every rule there has an empty allowlist by design**: a rule is only written if its allowlist *can* be empty after the migration it guards, since one needing exceptions is a matter of taste. That criterion is why there is no rule against native `title=` (documented as correct inside menus), against `animate-spin` (three legitimate spinning icons remain), or against bare `rounded` (right in principle, but the migration moves pixels app-wide while `--radius` is not theme-editable). The rejected rules are listed in that file with their reasons, so they are not re-litigated.
